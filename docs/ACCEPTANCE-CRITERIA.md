# Acceptance criteria — Phocommander M0, M1 and M2

This document holds one acceptance criterion for every requirement of the
milestones `M0`, `M1` and `M2` of the catalogue in
[`REQUIREMENTS-IDS.md`](REQUIREMENTS-IDS.md). The pattern follows the acceptance
rules of [`REQUIREMENTS.md`](REQUIREMENTS.md): every statement needs concrete
evidence, a command output or a test name with a green result. "It works" is not
evidence.

## How to read the criteria

| Column | Meaning |
|---|---|
| ID | `AC-M<n>-<nn>` — the criterion belongs to milestone `M<n>`. |
| FR-ID | The requirement of [`REQUIREMENTS-IDS.md`](REQUIREMENTS-IDS.md) this criterion belongs to. |
| How to Verify | The exact command or the exact operation sequence. |
| Pass Condition | A measurable statement. No "works", no "is implemented". |
| Type | `automated` — a machine-checkable command; `manual` — a described manual test step. |
| Evidence | The evidence that exists at the time of writing. |

## Rules for the evidence column

| Marker | Meaning |
|---|---|
| `PASS — evidence in deliverable.md` | The criterion was executed in this handover; the command output is quoted in `deliverable.md`. |
| `NOT RUN — <reason>` | The criterion could not be executed. The reason names exactly what is missing. A NOT RUN with a reason is allowed and honest; a faked PASS is not. |

A command that names a test which does not exist yet counts as `NOT RUN`, never
as a pass. The Rust crates referenced below do not exist in the repository at the
time of writing; they are created by the milestones of the specification
(`Systemarchitektur > Crate-Struktur`).
